# Questions for License Counsel

Please assess the exact proposed commercial deployment and answer in writing:

1. What AGPL-3.0 obligations apply when the pinned, unmodified Bidwright server is used by
   Frontdesk-Q Bridge over a network?
2. Which persons are considered users interacting with Bidwright "remotely through a computer
   network" under the intended architecture?
3. Does the fact that end customers and tenant users interact only with Frontdesk-Q change any
   source-availability obligations?
4. If Bidwright is unmodified, what source/code offer or access must be provided, to whom, and how?
5. If we later modify Bidwright, what additional source obligations arise?
6. Does container bundling, a single deployment stack, or a shared host affect the analysis?
7. Are there concerns with linking, combined works, plugins, copied types/code, or shared libraries
   across the Bridge/Bidwright boundary?
8. What notices, attribution, license text, UI links, or source links should Frontdesk-Q provide?
9. Are there restrictions or obligations concerning branding/removal of upstream marks?
10. What record-keeping process should engineering follow for future Bidwright upgrades and patches?
11. Would a customer-hosted deployment change the obligations compared with our hosted SaaS?
12. Are there jurisdictions/customer-contract terms that should be addressed before commercialization?

Engineering should not substitute its own interpretation for counsel's answers.
